# Rook

[English](README.md) · [Русский](README.ru.md)

Автономный агент, память которого можно прочитать.

Rook — локальный агент общего назначения (код, исследование, автоматизация),
написанный на Rust и поставляемый двумя статическими бинарниками без рантайма.
Всё, что он делает, он кладёт в компактное контентно-адресуемое хранилище и
считает *возможность это прочитать* функцией, а не отладочным довеском: CLI,
терминальный браузер и веб-интерфейс — три вида на один и тот же движок.

> **Статус: молодой проект, и об этом сказано честно.** Хранилище, система
> навыков, инструменты просмотра, цикл агента, стриминг, MCP, LSP и ACP
> реализованы и покрыты тестами — включая целые ходы по настоящему сокету против
> сервера, говорящего на диалекте провайдера. Способная модель теперь провела
> петлю от начала до конца: прочитала файл, сняла чекпойнт, внесла правку,
> запустила компилятор и ответила на проверку цели — одна модель и несколько
> ходов, то есть начало, а не послужной список. Ниже не описано ничего, чего
> нет; чего нет, перечислено в [«Что ещё не сделано»](#что-ещё-не-сделано).

Глубокая документация — на английском, ссылки в конце. Этот файл — полный
рассказ о том, что это и как этим пользоваться.

## Зачем ещё один

Каждое решение здесь восходит к конкретному публичному провалу агента, которым
пользуются люди: журнал в SQLite, пишущий терабайты в год; чекпойнты, сделанные
как `git add .` поверх рабочей копии на 45 ГБ; схемы инструментов ценой 5000
токенов за ход; переполнение контекста без возможности восстановиться.
Исследование с цитатами —
**[docs/research/agent-landscape.md](docs/research/agent-landscape.md)**.

Отсюда три следствия.

**Память компактна по устройству.** Контентная адресация, словари zstd,
обученные отдельно для каждого рода объектов, мелкие объекты — прямо в индексе.
На синтетическом наборе из 3000 ходов и 320 результатов инструментов это 20,5×
сжатия от начала до конца; цифру печатает `cargo xtask compaction`, так что её
можно проверить, а не поверить в неё.

**Отменяемость — свойство рабочей копии, а не журнала.** Перед каждой правкой
берётся снимок затронутых файлов; `rook session rewind` возвращает и разговор, и
файлы, включая созданные ходом. Никакого git — рабочая копия может быть не под
версионным контролем, и агент не должен об этом спрашивать.

**Ничего не делается за спиной.** Всё, что меняет машину, проходит политику
одобрений; запрет нельзя перебить ничем. Что агент прочитал, что запустил, что
запомнил и почему — читается тремя командами.

## Установка

Linux и macOS:

```sh
curl -fsSL https://raw.githubusercontent.com/ASlava12/rook/main/install.sh | sh
```

Windows:

```powershell
irm https://raw.githubusercontent.com/ASlava12/rook/main/install.ps1 | iex
```

Скрипт скачивает сборку под эту машину, сверяет её с `SHA256SUMS` релиза и
отказывается продолжать, если они расходятся, после чего кладёт два бинарника и
встроенные навыки под `~/.local` — больше никуда и без повышения прав. Он не
правит конфигурацию оболочки, а говорит, если каталог не в `PATH`. `ROOK_PREFIX`
кладёт в другое место, `ROOK_VERSION` фиксирует релиз, а сам скрипт — сотня
читаемых строк в этом репозитории, если вы предпочитаете сначала посмотреть, что
именно направляете в оболочку.

Из исходников (нужны Rust и компилятор C — две зависимости несут в себе C, см.
[docs/platforms.md](docs/platforms.md)); ни Node, ни Python, ни Docker:

```sh
git clone https://github.com/ASlava12/rook && cd rook
cargo xtask dist               # сборка, упаковка встроенных навыков, размеры
```

В релизах — `x86_64` и `aarch64` для Linux (статические, musl: работают на том
дистрибутиве, который у вас есть, а не на том, что был у сборочной машины),
`x86_64` для Windows и обе архитектуры для macOS. FreeBSD — поддерживаемая цель,
которая собирается и тестируется в CI, но опубликованного бинарника пока не
имеет: собирайте из клона.

## Как пользоваться

```sh
rook                                       # поговорить
rook run "перескажи, что изменилось в src/"   # один ход, потоком, для скриптов
rook chat --session last                   # продолжить с того места, где бросили
rook session show last                     # `last` работает везде, где ждут сессию
cargo test 2>&1 | rook run "почему падает?"   # stdin приклеивается к запросу
rook --json run "..." | jq .outcome.reply  # один объект: ответ, токены, изменения
rook tui                                   # разговор во весь экран, ^p — всё остальное
rook checkpoint create before-refactor     # или `c` во вкладке Checkpoints
rook docs add redis                        # прочитать документацию один раз и отвечать из неё
rook secrets add ssh_prod                  # пароль, который агент использует и не видит
rookd                                      # http://127.0.0.1:7717 — веб-интерфейс и API
rook daemon status                         # где он и та ли это сборка
```

Модель настраивается в `~/.rook/config.toml`:

```toml
[agent]
model = "anthropic/claude-sonnet-5"     # ANTHROPIC_API_KEY
# model = "lmstudio/qwen3-coder:30b"    # локальный endpoint, ключ не нужен
# model = "openai/gpt-5.5"              # OPENAI_API_KEY
# model = "google/gemini-2.5-pro"       # GEMINI_API_KEY или GOOGLE_API_KEY
# compaction_model = "ollama/qwen3:8b"  # сжатие контекста — не суждение, ему хватит модели поменьше
```

Через шлюз вроде OpenRouter — тем же диалектом:

```toml
[agent]
model = "openai-compatible/anthropic/claude-sonnet-5"
context_window = 200000
```

```sh
export ROOK_LLM_BASE_URL=https://openrouter.ai/api/v1
export ROOK_LLM_API_KEY=sk-or-...
rook models     # проверит, что адрес и ключ живые
rook doctor     # скажет, что реально дойдёт до этой модели
```

## Что он умеет

### Читать собственную память

```sh
rook session ls                  # сессии, их размер и стоимость
rook session show <id>           # транскрипт по номерам событий
rook session context <id>        # что реально уедет в модель на следующем ходу
rook store stat                  # сколько занимает каждый род объектов
rook search "почему мы так сделали"   # по всему, что сказано, прочитано и запущено
```

### Отменять сделанное

Перед каждой изменяющей операцией берётся снимок. `rook session diff` показывает,
что ход изменил на диске, `rook session rewind <seq>` возвращает и разговор, и
файлы — включая те, что ход создал. Отмена следует и за делегированием: то, что
написал подагент, откатывается вместе с родителем.

### Документация, которую он держит у себя

Модель, которую спросили про Redis, отвечает из того, на чём её обучали, — а это
было годовой давности в день выпуска, и об этом нигде не написано. `docs` —
альтернатива: сначала смотрит копию на этой машине, и только при промахе ищет
официальную документацию, читает несколько страниц и кладёт **результат
обработки, а не страницу**.

```sh
rook docs add redis              # прочитать один раз
rook docs show redis --question "как работает persistence"
rook docs add redis --refresh    # спросить источники, что изменилось
```

У каждого фрагмента ответа — оба адреса: локальная копия, из которой он собран, и
страница, по которой это можно проверить. Копия устаревает тогда, когда так
говорит источник, а не когда ей исполняется столько-то дней: у каждой страницы
хранятся `ETag` и `Last-Modified`, и обновление — это условный запрос, на который
неизменившаяся страница отвечает `304` без тела. Живой замер: сбор пяти страниц —
4,2 с, проверка тех же пяти — 0,65 с.

### Секреты, которыми он пользуется и которые не может утечь

Секрет назван, но не имеет значения везде, где его видит модель: она просит
`ssh_prod`, а значение подставляется на краю, внутри инструмента, в окружение
процесса, которому оно нужно.

```sh
rook secrets add ssh_prod        # ввод без эха; флага --value нет и не будет
rook secrets add npm --source env:NPM_TOKEN     # или сказать, где оно уже лежит
rook secrets ls                  # имена, источники, отвечает ли — но не значения
```

```
run_command { "command": "sshpass -e ssh deploy@prod 'systemctl restart api'",
              "secrets": ["ssh_prod"] }
```

Значения нет ни в транскрипте, ни в хранилище, ни в компакции, ни в наследстве
подагента, ни в запросе к провайдеру; то, что команда напечатает, возвращается с
вырезанным значением. `ssh` читает пароль только с терминала, поэтому команде,
назвавшей ровно один секрет, ставится `SSH_ASKPASS` на помощник, печатающий
унаследованную переменную. **Ни один вызов не возвращает значение** — ни CLI, ни
API, ни браузер; `show` не существует. Чего это не делает — не мешает модели
напечатать секрет нарочно; об этом прямо написано в
[ADR-0013](docs/adr/0013-secrets-are-named-never-valued.md).

### Проверять, а не верить

```
verify { "claim": "тесты проходят после правки", "settles": "cargo test -p rook-store" }
```

Проверяющий работает в своей сессии, без единого инструмента, который что-то
меняет, и обязан закончить вердиктом `holds`, `fails` или `unproven`. Вердикт от
проверяющего, который ничего не запустил и ничего не прочитал, докладывается как
`unproven`, как бы уверенно он ни звучал.

### Несколько проектов сразу

`rookd` держит хранилище, все окна работают рядом с ним. Одно хранилище на
машину, один писатель, у каждого проекта своя рабочая копия. `rook daemon status`
скажет, где он и та ли это сборка, что установлена.

### Что ему позволено

Всё, что меняет машину, идёт через политику: `allow`, `ask`, `deny` в
`[sandbox]`. Запрет окончателен — его не перебивает ни одобрение, ни хук, ни
подагент. Правила привязаны к позиции команды, а не к подстроке, и то, что прячет
команду от такой привязки, разбирается отдельно: `env -S 'rm -rf /'`,
`env --argv0`, тело `$(...)` и обратных кавычек.

## Три интерфейса, один движок

Новая возможность живёт в `rook-core` и доступна из CLI, из API и из TUI.
Возможность, доступная из одного интерфейса и недоступная из другого, считается
здесь дефектом.

## Что ещё не сделано

- Ни одного живого хода против Anthropic — нужен ключ.
- Релизные бинарники не подписаны: Windows SmartScreen предупредит, macOS
  Gatekeeper потребует «открыть» через контекстное меню.
- Полный список — в [docs/roadmap.md](docs/roadmap.md), включая то, что решено
  **не** делать и почему.

## Разработка

```sh
cargo xtask ci             # fmt + clippy + тесты — тот же гейт, что в CI
cargo xtask targets        # матрица поддерживаемых целей
cargo xtask compaction     # перемерить заявленные цифры сжатия
cargo xtask refs status    # насколько разъехались указатели на чужие репозитории
cargo xtask smoke --model … # настоящие ходы против настоящей модели
```
