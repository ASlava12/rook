### Настройки сессии и ожидание перед обновлением

`rook session model SESSION MODEL --effort high` атомарно сохраняет модель и effort для следующего хода. Уже запущенный ход сохраняет принятую пару. То же действие используют пресеты REPL/TUI и браузера.

`rook daemon drain --restart` закрывает приём новой работы и ждёт завершения текущей. `--status` показывает состояние, `--cancel PLAN_ID` отменяет план. Ответы на вопросы, отказ от приватного ввода и Stop остаются доступны; истечение срока не вызывает принудительный перезапуск.

Живое обновление инструментов MCP включается для выбранного сервера через `refresh_tools = true`. Границы обновления, сохранение привязок и статусы описаны в [руководстве](../mcp-catalog-refresh.md).

`rook session background SESSION` и `/background` показывают работу семейства сессий и фоновые команды, не переключая чат. В браузере есть такая же панель. [Описание статусов и границ обзора](../background-work.md).

`rook session last-answer SESSION` читает последний сохранённый ответ на текущей ветке; `/copy` явно копирует его. Внутренние сводки требуют `--summary`. `rook session results SESSION` и `/results` показывают типизированные результаты дочерних задач. Независимые fallback-цепочки и reasoning-настройки описаны в [руководстве R17](../reference-r17-adoption.md#usage). По умолчанию суммаризатор сохраняет лимит 2048 токена: сравнение качества отложено из-за исчерпанной квоты генерации API.

Для Gemini добавлено восстановление после `MALFORMED_RESPONSE` через общий
ограниченный механизм повторов. После передачи текста, reasoning или вызова
инструмента автоматического повтора нет. Повреждённые и отказанные генерации не
допускают исполнение вызовов инструментов; отказ в позднем кадре также прерывает
такой ответ. Сообщённые счётчики токенов неудачной попытки сохраняются, отсутствующие
остаются неизвестными. Прогресс текущей партии и оставшийся аудит/релиз описаны в
[журнале цикла](../reference-cycle-20261018.md).
