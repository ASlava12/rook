# Работа на несколько дней

В обычном чате `rook tui` задайте цель командой:

```text
/goal Реализуй согласованный план и проверь результат
```

Работа идёт **в текущей сессии**: сохраняются ID, предыдущая переписка и выбранные
модель, effort и режим разрешений. Новая сущность в интерфейсе не требуется.
У `/goal` нет общего потолка времени, шагов или токенов. Когда заканчивается
бюджет отдельного этапа, агент продолжает следующий этап в той же сессии.
Обычные сообщения вне активной цели используют обычные лимиты.

- Отправляйте уточнения прямо в чат. Сначала демон подтверждает получение (`↩`),
  затем появляется `✓ taken up`, когда уточнение включено в контекст.
- Повторный `/goal <текст>` меняет цель этой сессии; пустой `/goal` показывает её.
- **Ctrl+C** ставит цель на паузу после текущей операции; `/continue` продолжает.
- **Ctrl+P → sessions → Enter** переключает сессию, не останавливая работу.
  `/new` открывает новый разговор; `/session <id>` возвращает существующий.
- Закрытие окна не останавливает цель. После перезапуска `rookd` незавершённая
  цель возобновляется в той же сессии; поставленная на паузу остаётся на паузе.

Команда работает через общий демон, который обычный `rook tui` запускает сам.
Она также доступна в чате браузера и `rook chat`, подключённом к демону.
В локальном `--alone` `/goal` по-прежнему лишь сохраняет описание цели.
Разрешения операций не расширяются: используйте существующий выбор stance
(**F2**), если нужен автономный режим. Повторы после сбоев, обнаружение зацикливания,
границы контекста, ожидание инструментов и проверка завершения продолжают действовать.
Снятие общего бюджета не означает, что агент бесконечно повторяет ошибку или игнорирует
необходимые ответы пользователя.

## Необязательная отдельная панель Tasks

Откройте `rook tui`, нажмите **F4** или выберите **tasks** через **Ctrl+P**.
Вводить ID задач и команды не нужно:

- **n** — написать новую цель; **Tab** — включить автономное разрешение операций;
  **Enter** — запустить.
- **↑/↓** — выбрать задачу. Статус, ответ и проверка обновляются автоматически.
- **Enter** — написать уточнение для выбранной задачи; **Enter** — отправить.
  Поддерживается вставка абзацев, **Alt/Shift+Enter** добавляет новую строку.
- **p / r** — пауза / продолжение; **x**, затем **y** — отмена;
  **d** — удалить запись завершённой или отменённой задачи.
- **PgUp/PgDn** — прокрутить подробности; **Esc** — выйти из редактора или панели.

Уточнение сначала отображается как **Pending**, затем автоматически меняется на
**In context**, когда агент его забирает. Это подтверждение доставки, а не
выполнения требования. Обновление статуса не стирает черновик; при обрыве связи
текст и ID повтора сохраняются. Задачи продолжаются после закрытия TUI.

## Необязательный CLI

```sh
rook -C /путь/к/проекту task start "Реализуй согласованный план и проверь результат" --yes --seconds 604800
rook task list
rook task show TASK_ID
rook task steer TASK_ID "Сохрани совместимость публичного API" --message-id api-compat-1
rook task pause TASK_ID
rook task resume TASK_ID
rook task cancel TASK_ID
rook task forget TASK_ID
```

`--yes` разрешает операции, которые не запрещены deny list. Без него действует
настроенная политика, а запросы подтверждения без человека отклоняются.
Одна рабочая директория может иметь только одну незавершённую фоновую задачу.
Для параллельных задач используйте отдельные директории.

По умолчанию задача ограничена семью сутками и 10 000 итераций. Параметры
`--seconds`, `--tokens` и `--max-iterations` задают общий бюджет; ноль снимает
соответствующее ограничение. Ограничение одной итерации не завершает всю задачу.
Общее время включает паузы и простой. Проверка бюджета происходит на безопасных
границах: уже отправленный запрос модели может выйти за лимит токенов.

У уточнения есть два состояния: **сохранено / ожидает** и **включено в контекст**.
Второе содержит время и ID сессии; оно подтверждает доставку агенту, а не
выполнение нового требования. Текущий запрос модели или инструмент не
прерывается. Уточнение попадёт на следующую безопасную границу и сохраняется в
последующих итерациях и финальной проверке цели.

CLI ждёт подтверждения до 30 секунд; `--wait-secs 0` возвращает ответ сразу.
Позднейшее подтверждение видно в `task show`. При обрыве связи повторите отправку
с теми же `--message-id` и текстом: дубликат не создаётся. Для задачи на паузе или
в состоянии `blocked` отправьте уточнение и выполните `resume`.

В браузере вкладка **Tasks** показывает состояние и подтверждения автоматически.
В общем TUI доступны `/task list`, `/task start <цель>`,
`/task start-autonomous <цель>`, `/task show <id>`, `/task steer <id> <текст>` и
`/task pause|resume|cancel|forget <id>`. Подтверждение проверяется через
`/task show`. В режиме `rook tui --alone` фоновые задачи недоступны.

Временные сбои модели вызывают повтор с задержкой от 30 секунд до 30 минут.
Сессия и расход токенов сохраняются. Сбой дольше суток, проблемы с ключом или
кредитами, нерешённый вопрос либо повторяющиеся итерации без действий могут
перевести задачу в `blocked`. Причина доступна в `task show`.

Агент ведёт `.rook/plan.md`. Завершение требует независимой проверки актуальной
цели; если есть `.rook/evaluation.toml`, его проверки тоже должны пройти.
Уточнение, пришедшее во время проверки, запрещает завершить задачу по устаревшему
вердикту. Модельная проверка не гарантирует отсутствие ошибок.

Если процесс погиб во время операции с неизвестным результатом, автоматическое
повторение блокируется. Изучите `rook session recovery SESSION_ID`, проверьте
фактические последствия операции, затем используйте `--acknowledge` и `--note`
и продолжите задачу. Отмена не откатывает сделанные изменения.

`limited` означает исчерпание общего бюджета: `resume` его не обнуляет. Отмените
такую задачу и явно создайте новую с новым бюджетом. `forget` удаляет только
запись завершённой или полностью остановленной отменённой задачи, а не сессии.

Компьютер должен оставаться включённым и не спать. Для запуска после перезагрузки
настройте системный supervisor: systemd в Linux или launchd в macOS. Rook сам
службу автозапуска не устанавливает. После запуска `rookd` продолжение сохранённых
задач автоматическое. LaunchAgent запускается при входе пользователя; для работы
до входа нужна соответствующая системная служба или постоянно работающий сервер.

Полная таблица настроек `[work]`, пример службы systemd и HTTP API приведены в
[английской инструкции](../durable-work.md). По умолчанию сохраняются не более
64 записей задач, 128 уточнений на задачу и 16 последних сводок итераций;
достижение лимита уточнений возвращает ошибку без потери старых требований.

Старый `rook work` остаётся синхронным циклом для существующих скриптов.
Для многодневного фонового запуска и сохраняемых уточнений используйте `rook task`.
