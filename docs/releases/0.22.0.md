# Rook 0.22.0

Rook now supports agent collaboration across computers, scoped automation APIs
and a separate web workspace. The native CLI and daemon still require no Node
runtime; the optional interface runs with Node 24 or later.

## Agents and integrations

- Local delegated agents can exchange bounded messages through family mailboxes.
  Task-specific tool selections intersect the caller's authority.
- Native remote agents use signed requests and replies, durable receipts,
  idempotent delivery, live messages, status, paged results and cancellation.
  Operators explicitly enable peers, routes, workspaces and finite budgets.
  This is Rook's `rook-a2a-v1` protocol; it does not claim compatibility with
  other vendors' A2A protocols. See [remote agents](../remote-agents.md).
- External applications can submit and inspect the same managed tasks through
  a bearer-authenticated HTTP API or Streamable HTTP MCP server. Six MCP tools
  expose info, submit, status, message, result and cancel. HTTP and MCP share
  durable write receipts and route isolation. See [agent API](../agent-api.md).

## Web workspace

The interface includes projects, recent sessions, themes, a command palette,
Markdown, file mentions, an agent/context inspector and source-addressed diff
feedback. Bounded text drafts survive navigation and reconnects. Connection
recovery has an explicit status panel and read-only probes; it does not silently
resubmit prompts or cancellation requests. Invalid project paths can be replaced
through the folder selector. Closing the interface leaves the daemon running.

**Migration:** `rookd` now serves APIs and sockets only; it no longer serves an
embedded browser interface. Extract the optional `share/rook/web` directory from
the release archive and keep `serve.mjs` beside `dist/`. From an existing project:

```sh
rook daemon start
node /path/to/extracted/share/rook/web/serve.mjs --daemon http://127.0.0.1:7717 --port 3000
```

Open `http://127.0.0.1:3000`. Use the actual printed daemon URL if its configured
port differs. One daemon owns each store; `daemon start` reuses the existing
instance. Replace example paths with real folders. The installers and `rook update`
install native binaries and skills; copy/extract the optional UI separately when
updating it. See the [web instructions](../../web/README.md).

## History and long tasks

- History search uses full Unicode case folding, preserves original UTF-8
  coordinates and shows snippets around matches even in long lines. Literal
  multiline searches retain the original whitespace. See [history search](../history-search.md).
- Compaction retains a bounded companion list of file requests with source
  sequence references. Requests remain distinct from proof of completed edits.
  Summary/checker inputs and prior-summary fallback have explicit size bounds.
- Registered credential values are masked before compaction requests and in
  saved summaries and failure reasons. Existing source records remain unchanged;
  this covers registered values, rather than arbitrary secret discovery.
  See [compaction](../long-task-compaction.md).

This release also includes the unpublished 0.21.21 changes: responsive background
TUI panel reads, cross-window cancellation, local MCP shutdown and hook stdin
cleanup. See [their detailed notes](0.21.21.md). The separate parallel `/btw`
development branch is outside this release.

Reference pointers and the implementation inventory were refreshed, with pinned
source evidence in [the November review](../research/reference-review-20261112.md).
Windows builds use `xtask/cargo.cmd` to keep build output and temporary files on
the workspace drive. `caseless` 0.2.2 (MIT) supplies Unicode folding; embedded-web
dependencies were removed. The minimum supported Rust version remains **1.90**.
No store schema migration is required.

The original managed-work timeout observed while verifying the older 0.21.21
draft remains unexplained. That draft and its assets are retained unchanged;
new runtime checks and their limits are recorded with this release's verification
evidence. Controlled fixture checks establish the exercised behavior, not model
quality or interoperability with every remote environment.
