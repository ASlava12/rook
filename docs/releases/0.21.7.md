# Rook 0.21.7

- Concurrent transient provider retries add a fresh nonnegative random delay of
  up to 25% above the ordinary exponential backoff or provider-advised minimum.
  Added delay stops at the existing 120-second advice ceiling; a larger minimum
  supplied by a custom provider is retained without extra delay. Four ordinary
  attempts wait at most 8.75 seconds in total. Complete requests, stream opening
  and errors before the first content delta share the same path. Terminal errors,
  partial answers, confirmed completion and request-local credit recovery retain
  their previous retry rules. Fractional waits appear in debug logs.
- Navigable transcript and `session_recall` reads admit session metadata at
  64 KiB and event metadata at 16 KiB before decoding variable-length fields.
  Admission includes pages, search batches, entries, quotes, explicit image reads,
  previous/next probes and neighboring timing/change/detail/image records.
  Oversized metadata produces an explicit error naming its session or event;
  it is not silently removed or treated as proof that an action never happened.
- Forward history reads apply the frozen exclusive head at the database range,
  before metadata admission. Search continuations, pages and their timing notes
  cannot fail because of unrelated events appended beyond that head. Matching
  in-range measurements and the existing live individual-entry lookup remain
  available.
- Existing cursor and fork semantics, result/companion linkage, the original
  journal and explicit retrieval of large saved bodies are preserved. Legacy
  non-navigable service readers retain their previous contract. Verified compressed
  range reads still traverse whole objects and copy inline encoded payloads;
  these metadata limits do not establish whole-read heap, I/O or latency bounds.
- A reproducible four-process HTTP 429 fixture now runs on Linux, Windows and
  macOS in source CI and is required for downloaded-package verification when
  retry scheduling changes. It checks eight functional conditions and records
  physical retry timings. Statistical spread is observational; deterministic
  injected-sampler tests separately establish jitter's added wait and ceilings.

`fastrand` 2.5.0 becomes a direct dependency but was already locked. External
package/version/checksum records are unchanged. No new configuration key, store
format or MSRV change. Internal Cargo path dependency requirements match the
workspace release version. The implementation independently adapts the pinned Hermes
retry-jitter idea and extends Rook's metadata admission after the Pi committed-range
review; no upstream implementation is copied. See
[reference credits](../../references/PORTED.md) and the
[transcript contract and limits](../transcript-admission.md).

Publication requires the full source preflight before the workspace version bump,
all eight required jobs on the exact final versioned source, all five downloaded
archive/provenance/skills/linkage checks, both host versions and 110 conditions on
the extracted Windows package: managed work22, background installation10, release
metadata6, independent publication8, ACP28, credit10, HTTP-date8, checker history10
and concurrent retries8. All six public assets must match the tested draft after
publication. See [release verification](../releasing.md).

Optional real-model smoke is separate evidence, including its failures. Scripted
checks and retry timing observations do not establish task quality or production
throughput. The real-transcript compaction experiment remains pending and the
default summary allowance stays 2048. No installed user daemon/session/state is
updated or restarted by this release verification.
