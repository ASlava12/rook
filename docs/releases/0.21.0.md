# Rook 0.21.0

- Browser flows can answer native JavaScript alerts, confirmations and prompts
  through the ordinary `browser` tool. Responses use explicit accept/dismiss,
  bounded optional prompt text and a fresh context bound to the conversation,
  browser generation and latest driver call. Stale or consumed contexts fail
  before dispatch; unsupported actions cannot start or poison a browser.
- Browser observations check actual page/status results before cycle detection.
  Stable observations still stop after 20 identical results, and mutations keep
  their existing repeated-call protection.
- Command progress comparison ignores fresh undo receipt IDs and presentation
  notes for complete captured results. Truncated displays with complete retained
  captures compare the actual bytes, including the hidden middle, instead of
  newly generated filenames. Reads require a regular file in the private output
  directory and fit an 8 MiB bound or the smaller configured spill cap.
- Fresh explicit guidance or a new queued-message edit wakes an ordinary managed
  retry wait. Duplicate deliveries do not wake another attempt or reset idle
  accounting. Failure counts and budgets remain enforced; paused/blocked goals
  and explicit deferred-work deadlines retain their controls.
- Live conversation activity shows an expected retry and its deadline instead
  of an active model request. The scheduled wait does not invent progress or
  trigger a model-stall notice. An overdue scheduler remains monitored, and
  older saved activity records remain readable.
- Browser QA guidance describes offered dialog, diagnostic and viewport controls
  accurately, including the limits of viewport-only mobile checks.

The dialog capability independently adapts the pinned Hermes reference using
Rook's existing pinned Playwright MCP driver; no upstream browser bridge is
copied. See the [browser reference and verification record](../research/browser-dialogs-20261021.md),
[browser contract](../browser.md) and [managed retry guidance](../managed-retry-guidance.md).

Verification combines engine/persistence tests, owned native Windows Chromium
journeys and platform gates. The Unix-only native browser cleanup test was not
exercised on Windows. Scripted tests do not establish improved live-model task
quality. Final platform results, optional model smoke outcomes and archive
verification limits are retained in the linked evidence.

Tagged builds stage a draft. Source gates and downloaded-asset checks must pass
before that same draft is published, following the [release procedure](../releasing.md).
