# Rook 0.21.3

- Overlapping cache installs in one daemon share one operation across independent
  callers and workspaces. Metadata lookup, checked download/build and publication
  are owned together. This avoids duplicate downloads and conflicting writes to
  the same current-server path.
- Each session retains its own durable background-install intent and result.
  Cancelling one caller leaves work available to the others; cancelling all
  callers drops the shared operation using existing cleanup. A later explicit
  install can retry after either success or failure.
- Distinct source, release API, proxy or target profiles targeting one cache
  command wait for the current owner, then perform their own operation. Different
  cache directories and commands continue independently.
- Admission bounds active operations at 64. Matching callers may join at
  capacity; a new destination is refused before HTTP or cache mutation. Cache
  identity resolves existing path components without creating directories.
- A new owned package probe drives two ordinary chats in different workspaces
  against one temporary cache and scripted local services. It verifies one
  physical download, both callers' retired receipts and the checked payload.

The published 0.21.1 baseline reproduces duplicate downloads; in a controlled
Windows case one background install fails with `os error 32` while the other
succeeds. The corrected local daemon passes all ten native probe checks. Release
artifacts require their own verification before publication.

Ownership is process-local and covers installs through the cache installer.
Separate CLI/daemon processes and system package-manager installs retain their
existing coordination. There are no new dependencies, configuration keys or
stored formats; the MSRV remains 1.90.

See [install ownership](../lsp-install-concurrency.md) and
[release verification](../releasing.md). The design independently adapts an
in-flight Roslyn installation pattern reviewed in historical OpenCode; no
upstream code is copied and reference pointers are unchanged.
