# Rook 0.21.9

- Environment discovery runs independent language/tool version commands with at
  most four active probes per detection. The caller participates alongside up to
  three temporary workers, so waiting on slow version shims no longer accumulates
  across all sixteen entries in sequence.
- Results retain their original inventory slots and deterministic language/tool
  maps even when a later command finishes first. Missing tools remain absent.
  If a worker cannot be created, the caller and remaining workers drain unclaimed
  entries. Existing per-command patience, parsing, hidden-process setup and
  direct-child cleanup remain in force.
- A portable owned fixture invokes the actual JSON doctor against all sixteen
  controlled version programs. Serialized loopback events verify real overlap,
  the four-probe cap and exact single executions; exact maps, no model requests
  and unchanged workspace/binary provide independent controls. Source CI runs it
  on Linux, Windows and macOS, and release verification requires all eight flags
  on the extracted host package.

The cap is per detection, not global across independent agent processes. This
does not establish a deadline for the whole application startup or change the
existing subprocess output/descendant contract. No persistent cache,
configuration key, dependency, schema or MSRV change. Internal Cargo requirements
match the workspace release version.

The implementation independently adapts the bounded, ordered probe idea from
pinned Hermes `22063fc099ec9ad8357d7f8f6e6248a0400680d3`,
`hermes_cli/doctor_connectivity.py::run_probes`. Hermes uses eight HTTP workers;
Rook uses four local-process slots. No upstream implementation is copied. See
the [runtime contract](../environment-probes.md),
[owned fixture](../../xtask/probes/environment-startup/README.md) and
[reference credits](../../references/PORTED.md).

Owned Windows development measurements with sixteen two-second tools took
8.5 seconds with peak four, compared with 33.2 seconds and peak one on the
published exact-base 0.21.8 CLI. The old implementation failed only the
parallel-execution flag and passed all seven independent controls. These compare
a local development binary and a published release using controlled sleeps;
they do not establish production throughput or model task quality. Final source
and extracted-package results are separate release evidence.

Publication requires full preflight before the version bump, eight mandatory
jobs on the final versioned source, five downloaded archive/provenance/skills/
linkage checks, both host versions and 134 native conditions on the extracted
Windows package: managed work22, background installation10, release metadata6,
independent publication8, ACP28, credit10, HTTP-date8, checker history10,
concurrent retries8, provider waits16 and environment probes8. Publish the same
tested draft, then compare all six anonymous public assets. See the

real-transcript compaction experiment remains pending and the default summary
