# Rook 0.16.0

Rook 0.16.0 adds durable model choices, a cross-session attention inbox and explicit conversation-sharing profiles, with shared CLI, API, terminal and browser support.

- Model choices survive restart and apply at the next root turn boundary. Identified retries return their original receipt without replacing a newer choice; status distinguishes selected and last-effective models.
- The attention inbox finds current questions, permissions and private-input requests across sessions, with parent/child navigation. Saved observations never become authority to answer an expired request.
- Optional daemon diagnostics distinguish scheduler lag, admission waits, blocking queues and elapsed work. Enable `[telemetry.runtime_diagnostics] enabled = true` at daemon startup. Observations never kill or retry work automatically.
- Conversation exports add `share`, `share-tools` and `archive` profiles, a bounded preview and an omission manifest. The browser previews the exact artifact before download.
- Each configured model can override compaction trigger, output reserve and retained-history target under `models.<name>.compaction`.
- Recipes can declare required tools/MCP servers and restrict equipment. Nested runs inherit intersections; preflight fails before a model request when requirements are unavailable, and dispatch enforces restrictions even for unadvertised calls.
- `ROOK_PROGRAM_STATUS=on` enables OSC 7501 lifecycle/waiting states in text TTYs. Frames contain no task or secret text and are suppressed in JSON and redirected output.
- SSH snapshot transfers use certified version-2 chunks, bounded parsing, private staging and atomic per-file publication. Existing recovery receipts and preimage checks remain in force.
- Secret writes explicitly release locks on completion, preventing false contention when a parallel process inherited a descriptor. PTY checks preserve split UTF-8 characters across reads.
- All ten reference pointers advance to the reviewed snapshots; the adoption ledger records provenance and supported scope.

Compatibility: `share` is now the default export profile and includes user/assistant prose only. Choose `share-tools` to include tools or `archive` for readable internals. Streaming SSH peers must support version 2; incompatible peers are refused. Persisted store format and Rust 1.90 minimum remain unchanged.

Validation: the complete local `cargo xtask ci`, browser module suite, production SSH-worker filesystem probes and native daemon/HTTP/PTY fixture passed. Full live SSH authentication and remote process-lifecycle verification remained unavailable because the trusted LAN endpoint was unreachable and the local container fixture was stopped.

See [the adoption guide](../reference-r16-adoption.md) for commands, settings, reproducible probes and verification limits.
