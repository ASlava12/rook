# Rook 0.21.11

- PATH language-server discovery keeps the observed exit status separate from
  cleanup. A zero exit is accepted, a nonzero exit is refused, and a probe still
  running after ten seconds remains eligible consistently across platforms.
  Every outcome requests owned-group/direct-child cleanup, including parents
  that exit while descendants remain. Reap polling is bounded. Installed
  language-server payloads retain their detection bypass.
- Remote skill caches use a bounded readable label and the complete SHA256 of
  the exact configured address. Distinct addresses such as `/a/b` and `/a-b`
  cannot share a punctuation-normalized directory. Legacy caches stay in place;
  a subsequent explicit search fetches into the new address-specific cache.
  Labels avoid Windows device-name paths such as `CON.foo`.
- Explicit skill installation origins and saved update origins also retain
  exact remote addresses. Previously removing `.git` or a trailing slash could
  select a same-named skill from a different endpoint. Equivalent local paths
  still canonicalize; local-edit protection and existing installed content
  remain. An intentional remote-address change uses
  `rook skills install NAME --source ADDRESS` rather than assuming aliases.
- The actual CLI source-identity fixture verifies three owned smart-HTTP
  repositories, cold/warm/refresh behavior, legacy-cache preservation, and
  exact manifest/resource bytes after explicit-origin installation and update.
  Its ten conditions prevent accepting cache separation as a complete origin
  fix. The LSP discovery fixture separately checks eleven conditions and the
  daemon shared-pool regression checks eight.
- The Russian README introduction is written from a checked UTF-8 template,
  correcting the question marks introduced by the previous version-preparation
  shell pipeline. Both language introductions are checked before version commit.

The provider-wait CI observer records and retries transient read-only diagnostics timeouts within its original three-second request and 120-second scenario limits. Three consecutive timeouts remain a failure; all eight physical/status conditions remain mandatory. An initial Windows source attempt stopped on one such diagnostics timeout; controlled single-timeout and persistent-timeout probes distinguish recovery from hiding an unresponsive endpoint. This changes fixture observation reliability, not provider backoff or production API latency.

Process creation/signalling remains synchronous. Direct-child cleanup may poll
for one additional second; Darwin group cleanup retains its five-second grace.
Windows job attachment follows spawn and detached descendants retain existing
ownership limits. Discovery remains sequential across known language servers;
this is not an overall startup deadline or a universal containment guarantee.
Workspace applicability still follows full automatic PATH discovery in this
source. A separately tested metadata-first admission change is tracked in
[PR31](https://github.com/ASlava12/rook/pull/31) and is not included in this release.

Remote origin matching now distinguishes case, escaping, query values, trailing
slash and `.git` spelling. Existing configured addresses continue to match their
saved exact origin. A changed address requires explicit selection. The digest
identifies a configuration string; transport authentication and content trust
continue through the existing Git and skill-install controls.
