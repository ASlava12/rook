# Rook 0.21.14

- Direct local foreground Cargo build/check/test/clippy/doc/bench results omit
  ordinary package progress and passing-test lines before the display cap.
  Compiler diagnostic continuation text remains data, even when it resembles
  progress. The existing original capture is retained, including for a short
  condensed reply; `output="raw"` keeps the original presentation.
- `crate_api` accepts an exact locked `version` and refuses ambiguous versions
  or same-version source records. It uses the nearest Cargo.lock and does not
  fall back to another workspace after an unreadable/invalid lock or absent
  package. The corresponding cached `.crate` archive must match the full locked
  SHA256 before local source scanning. Linked source roots are refused with
  explicit incomplete coverage.

Cargo condensation requires an opened owned original-output capture. Background,
editor, remote/container execution and unrecognized wrappers or compound commands
retain their existing presentation. The selector is not an authorization parser.
Original capture retains existing secret masking and its size cap; incomplete
capture is never called complete. Filter buffering admits at most 16 KiB per
stream line. Long, partial, non-UTF8 and unknown-control data are retained, and
ordinary display limits still apply. Arbitrarily large diagnostics may be elided.

Crate lookup uses Cargo.lock package names, not renamed manifest aliases.
Package/version selectors admit up to 128 ASCII letters, digits, `_`, `-`, `+`
or `.`; other forms are refused rather than used as cache path components.
Path/git dependencies remain unsupported. Cached archive identity does not
attest every extracted file; current local source edits remain visible. Source
root admission is not an atomic snapshot against concurrent cache changes.
There is no implicit fetch, compiler invocation or additional model request.

Lock admission permits 4 MiB plus one refusal byte. Local registry enumeration
admits 256 entries. Archive hashing streams with a 16 KiB buffer, a 64 MiB plus
one-byte candidate ceiling and a shared 256 MiB read budget. Source traversal
admits 4,096 entries, 512 Rust files and sixteen levels; reads share 8 MiB with
256 KiB per file. The existing 200-item display cap has bounded candidate/output
storage and explicit incomplete-scan notices. These reader/presentation limits
are not a whole-process memory bound or elapsed-time guarantee. The scanner does
not perform rustdoc type resolution or conditional-compilation evaluation.

See the [Cargo contract](../cargo-output-condensation.md),
[crate identity contract](../crate-api-identity.md) and
[reference credits](../../references/PORTED.md). Both adaptations followed Haico
at `5b352f3c7e3b608e68ec49af65a66feb098e07d4`: `src/tools/cargo_output.rs`
prompted independent streaming capture integration, and `src/tools/build_notes.rs`
prompted the prerequisite local API audit. No upstream implementation was copied.
Automatic error-aware documentation hints are not added here. The separate
cached-documentation version-neighbor correction is not included in this source.
