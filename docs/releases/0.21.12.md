# Rook 0.21.12

- Automatic language-server discovery checks bounded workspace metadata before
  running PATH version commands. Notes-only folders execute no server probes;
  Python-only folders avoid unrelated Rust, TypeScript, Go and C commands.
  Full inventory APIs, known ordering, explicit configuration replacement and
  installed-payload probe bypass remain. A configured language with custom
  extensions is not offered for automatic installation over that choice.
- Support reports admit saved metadata before decoding variable-length fields.
  Primary sessions and each of at most 64 ancestors admit 64 KiB. Oversized
  primary metadata is refused, including HTTP workspace routing. An unavailable
  ancestor omits correlation with a notice while the rest of the report survives.
- The captured recent event range retains its configured 1..2048-entry ceiling,
  with 4 KiB of raw metadata per record. Oversized/unreadable records are omitted
  explicitly; readable neighbors and current activity generation/progress survive.
  The ordinary range uses one transaction; exceptional recovery reads only exact
  captured slots and cannot admit later appends. Saved records and bodies remain.
- Complete and invalid session identifiers are parsed before local or HTTP
  session listing. The `last` alias retains its existing enumeration semantics;
  that selection step is outside these per-report reader bounds.
- Owned source/runtime controls cover six workspaces and twelve CLI conditions,
  plus eighteen diagnostic conditions through local CLI, direct HTTP and remote
  CLI. A loopback proxy witnesses listing bypass. A content digest verifies all
  seeded session/event metadata, bodies and activity before/after report reads.
  The helper only seeds/verifies private data; the requested CLI/daemon pair
  performs every report read. Helper dependencies are resolved offline against
  the source lockfile and their identities are checked.

Workspace matching retains its existing 4,000-entry/six-level scan budget,
ignore rules and no-follow-link behavior; it is not a complete filesystem index.
Applicable discovery remains sequential with its existing ten-second probe
patience and documented process-ownership limits. No total startup deadline is
introduced. Explicit configurations and installed payloads keep their contracts.

Two fixture corrections preserve the tested lifecycle boundaries. The restart
fixture accepts that a committed completed record may precede worker cleanup:
it retries only the specific finishing-operation deletion refusal within its
existing ninety-second deadline. Oversized version helpers omit an optional
completion connection after their banners, since output-limit enforcement may
terminate them between TCP connect and frame write. Their sixteen acknowledged
starts, exact version maps, eight capture flags and malformed-frame failures
remain mandatory. Initial Windows deletion and Linux observer failures are
retained separately; neither is accepted as a passing source gate.

The report serialization ceiling stays one MiB. Existing receipt/body/log input
limits remain separate: activity 2 KiB, execution JSON 8 MiB, timing 1 KiB, model-attempt
bodies 4 KiB and opt-in log tails 64 KiB each. These limits are not a claim that the
whole process uses one MiB, nor an end-to-end API latency guarantee. They do not
establish the cause of an earlier three-second CI observer timeout. Ordinary full
inspection can still read metadata omitted from support output. No new runtime
dependency, configuration key, persisted format, storage migration or MSRV.
