# Rook 0.22.1

Ordinary model requests now leave sampling temperature to the server. Rook no
longer silently sends `temperature: 0`, which could override model-specific
settings on local endpoints such as Gemma. Chat Completions, Responses and
Google adapters omit an unset temperature, including streamed requests.
Explicit numeric overrides remain supported where the adapter accepts them;
OpenAI reasoning families still omit unsupported sampling parameters.

Model-call recordings distinguish `temperature: null` (server default) from an
explicit number, including zero. Existing numeric captures remain readable and
eligible under the same content rules. The capture records the caller's request,
not the server's effective sampling settings.

The streamed repetition guard remains enabled by default. This change fixes an
unwanted request override; it does not establish the cause of the original Gemma
repetition incident or exclude MTP and other server/model effects. No live-model
quality claim is made.

**Library API:** `rook_llm::Request::temperature` changes from `f32` to
`Option<f32>`. Use `None` to preserve server defaults and `Some(value)` for an
explicit override. The output-schema repair path retains its explicit zero.
Rook publishes binary archives rather than crates.io packages.

No configuration migration, store schema migration, dependency or minimum Rust
version change is required. The agent integrations and standalone web migration
from [0.22.0](0.22.0.md) continue to apply.

Validation includes complete workspace formatting, Clippy, frontend builds and
tests before the version bump; HTTP fixtures cover unset/zero/0.6 temperatures,
streaming, reasoning-family omissions and capture compatibility. Release-revision
platform CI, downloaded-archive verification and native runtime evidence are
reported with the published GitHub release.
