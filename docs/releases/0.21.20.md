# Rook 0.21.20

The terminal interface can open a saved conversation with `rook tui --session <id|last>`, including `--alone`. An explicit session ID follows the recorded workspace; an explicit conflicting workspace is refused. An attached window rejoins the existing turn without submitting another prompt and displays the turn's live permission and effort settings. Missing workspaces and older daemons without the metadata endpoint receive an actionable explanation before the terminal interface opens.

Failed prompt hooks now refuse admission before the user message is saved or the model is called. Observer hooks remain best effort. Ordinary hook timeout errors identify which stdin, stdout, stderr and process waits completed. Boxing the hook invocation future prevents a reproduced Windows main-stack overflow during nested agent/ACP execution, including turns with no configured hooks.

Terminal shutdown guidance uses the portable `rook daemon stop` command.

Known existing limitations: stopping a daemon turn from another window can leave the original `rook run` waiting after cancellation. On Windows, `session ls` can omit sessions when the same workspace has different path spellings; `session ls --all` exposes them. Corrections and asynchronous panel refresh are implemented in a separate development branch and are outside this release.

No dependency or minimum Rust version change is included.
