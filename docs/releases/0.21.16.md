# Rook 0.21.16

Rook can record canonical provider requests and visible replies for local
inspection and review of possible regression or training examples. Recording
is disabled by default. Enable one turn with `rook run --record-model-calls`,
or choose `on`, `off` or `config` with `/record-model-calls` in chat.

`rook session model-calls SESSION` previews identities, purposes, coverage and
exclusion reasons. `--format records --output calls.json` saves admitted visible
payloads. `--format dataset --output pairs.json` saves complete supported pairs
for review. Both use a frozen inclusive event range and publish only to a new
local file. CLI and daemon use the same bounded reader.

Each example keeps its own captured system/messages, tool schemas, request
settings, physical dispatch and input/output provenance. Only its response is a
target. Retries and failover remain separate attempts; compaction and later
catalog/model changes do not rewrite snapshots. The four reproduced Haico
history-fidelity cases remain separate exact examples.

Known-secret masking applies to strings and keys. Images, hidden reasoning and
provider replay state are omitted before capture. Redacted or incomplete
context, missing/partial/max-token replies and invalid tool relationships are
excluded from datasets with reasons. Every example remains unlabelled and
requires review: confirmed completion does not establish correctness. This is
a Rook review format, not raw HTTP bytes or a trainer integration. No recording
setting performs an upload or training. See [format and limits](../model-call-recording.md).

Maintained Rust articles now have `cargo xtask check-docs`. An explicit index and
independent pinned/offline manifests keep selected examples reproducible. The
checker verifies the selected main and test artifacts, typed expected compiler
errors and immutable inputs. `--run` opts into both executable targets while
respecting `no_run` and `ignore`. The ownership and serde_json articles contain
nine checked blocks; hosted CI retains receipts on Linux, macOS and Windows.
Missing dependencies, infrastructure failures and absent artifacts cannot
become successful example checks. See [the checker contract](../examples/README.md).

These features were independently implemented after examining Haico at
`5b352f3c7e3b608e68ec49af65a66feb098e07d4`; no upstream implementation was copied.
