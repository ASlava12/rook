# Rook 0.21.10

- Version discovery keeps its patience active while waiting for both output
  streams, even after the direct parent exits. A descendant holding a pipe can
  no longer turn the final output read into an unbounded wait.
- The shared containment layer drains ready data while the child runs and checks
  a combined output ceiling before retaining bytes. Version commands receive
  64 KiB across stdout and stderr. Timed-out, oversized or unreadable captures
  discard partial versions while other successful inventory entries survive.
- Failed captures request owned-group/direct-child termination and bounded
  direct-child reap polling. No detached reader threads are introduced. Platform
  glue remains in rook-contain; the existing Windows binding gains pipe queries
  without adding a crate, configuration key, store schema or MSRV requirement.
- A portable actual-CLI fixture shadows all sixteen inventory names and checks
  six output/lifetime cases plus unavailable stubs. Its eight conditions cover
  exact versions/calls, a thirty-second pipe holder governed by the shorter
  patience, owned holder-connection retirement, no model HTTP requests and
  unchanged workspace/binary bytes. Source CI runs it on Linux, Windows and macOS;
  release verification requires the same conditions on the extracted host CLI.

Process creation and platform signal calls remain synchronous. Failure cleanup
can additionally poll reaping for one second; Darwin group cleanup retains its
existing five-second grace. Windows job attachment occurs after spawn, and
detached descendants retain existing ownership limits. This is not a whole
application startup deadline or a universal process-containment guarantee.

The implementation extends the existing Hermes-inspired short-command patience
after reproducing the Rook parent-exit/pipe gap. The pinned reference is Hermes
`22063fc099ec9ad8357d7f8f6e6248a0400680d3`,
`hermes_cli/doctor_tools.py::_run_ok`; the ready-pipe reader is an independent
Rook implementation, not a port of an upstream capture API. No upstream code is
copied. See the [runtime contract](../version-probe-capture.md),
[owned fixture](../../xtask/probes/version-capture/README.md) and
[reference credits](../../references/PORTED.md).

Owned Windows development diagnostics passed all eight conditions in 5.12 seconds.
The same helper on the published 0.21.8 serial build took 41.03 seconds and
reproduced three expected violations while retaining five independent controls.
These controlled diagnostics compare different build profiles and do not
establish production throughput or model task quality. Initial Windows CI also
exposed a fixture isolation defect: native lookup found the runner's Docker
outside the reduced PATH. Shadowing all sixteen names corrected that setup
without weakening the expected maps or the capture conditions.
