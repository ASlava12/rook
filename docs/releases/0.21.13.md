# Rook 0.21.13

- Independent PATH language-server discovery probes run up to four at once.
  Candidate order remains stable even when processes finish in a different
  order. Workspace admission happens before probes; explicit configurations and
  installed-payload bypass retain their existing behavior. The caller consumes
  work too, including when another worker cannot be spawned.
- Anthropic image-only user messages and native tool results omit blank text
  blocks beside images. Real captions retain exact bytes. Image order, media
  types, payloads, tool identifiers and batches remain unchanged. Cacheable
  image-only user messages place their existing cache boundary on the last image,
  retaining default five-minute caching and explicit one-hour TTLs. Text-only
  empty/whitespace tool results keep their original data.
- Release-asset downloads retain a received prefix within the current invocation
  and retry an interrupted body up to three application attempts. A resumed
  response must describe the exact remaining range and a consistent bounded
  total. A full response ignoring Range restarts the body and hash. Completed
  downloads must match the full advertised SHA256 and size before extraction or
  installation. HTTP, encoding, range, size and digest refusals remain terminal.

The discovery cap belongs to each call, not the whole daemon. Existing probe
deadlines and process-ownership boundaries remain; no total startup deadline is
introduced. The controlled five-pending-command fixture observes concurrent
execution and checks the four-probe cap and stable output, without a latency
threshold or production performance claim.

The image correction covers valid bare-image history and native image tool
results. Normal frontends already add nonblank user framing. Owned CLI and daemon
replays exercise legacy bare-image messages, both cache TTLs and unchanged saved
input; they do not establish a live Anthropic API refusal or a current GUI
submission failure.

The downloader requests identity bytes and disables transparent decompression
and hidden client retries. One ten-minute asset-fetch budget covers redirects,
body reads and all three attempts; metadata lookup and the rest of an update are
separate operations. Received bytes are retained in memory only for this call,
not as a durable resume file. The retained asset limit remains 256 MiB; existing
metadata/extraction bounds remain separate, not a whole-process memory claim.
Old installed binaries acquire this recovery behavior only after upgrading.
