# Rook 0.21.5

- ACP clients can advertise editor reads and writes independently. A write-only
  client now receives editor write requests instead of silently changing disk.
  Unsupported operations use the original bounded filesystem context, preserving
  workspace/path policy. No unadvertised editor method is requested. Existing
  child-session forwarding and the restriction on editor bridges in isolated
  worktrees remain in force.
- An HTTP 402 refusal that explicitly states an affordable integer output budget
  can trigger one retry with a smaller allowance. The retry leaves a 64-token
  margin, requires at least 1024 output tokens and never raises the caller's
  allowance. The balance is not cached as a permanent model limit. A repeated
  payment refusal, missing/malformed budget or already sufficient allowance
  retains the existing error/fallback behavior. Streaming requests retry only
  before response content or completion evidence; partial output is never
  replayed automatically.
- The owned CLI credit probe covers seven isolated runs and ten conditions,
  with bounded HTTP bodies, output capture and execution time. The ACP probe
  retains its original eighteen recovery/result conditions and adds ten
  independent-capability conditions with distinct disk/editor markers.

No new dependency, configuration key, database format or MSRV change. The
implementation independently adapts the pinned ACP client schema and Hermes
credit-recovery idea; reference pointers are unchanged and no upstream code is
copied. See [reference credits](../../references/PORTED.md).

Source preflight completed formatting, workspace/all-target clippy, current
frontend builds and the complete workspace test suite on Linux. The corrected
source passed the early actual-CLI ACP28 and credit10 steps on Linux, Windows
and macOS. These scripted checks establish runtime/protocol behavior rather
than live-model quality. The real-transcript compaction comparison remains
pending and its default output budget stays 2048.
