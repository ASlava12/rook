# Rook 0.21.8

- Provider refusals now expose their already sampled retry delay, next physical
  attempt and optional HTTP status. CLI, TUI, ACP and browser views show why the
  request is waiting. Advisory data contains no prompt, credentials or provider
  response body, and does not admit or bill another generation.
- Activity snapshots add a bounded optional provider_wait deadline, distinct from
  the durable scheduler retry_at. Known provider waits do not produce false
  inactivity notices or reset last_progress_at. A retry still overdue after the
  configured threshold remains observable; repeated status cannot postpone that
  check. New physical requests receive normal no-output monitoring.
- Physical admission, cancellation and owner termination clear advisory status.
  Child waits retain their own activity projection and also reach the parent's
  bounded display-hint channel. A child's deadline does not replace the parent's
  model deadline or disable the parent's ordinary inactivity checks. Historical
  observations remain explicitly historical and never authorize replay.
- Owned HTTP/WebSocket fixtures exercise main and completion-classification
  retries on Linux, Windows and macOS source CI. Each mode requires eight flags:
  call counts, retry minimum, visible/scoped status, retained idle evidence,
  absence of false stalls and unchanged binaries/workspace. Runner tool discovery
  is isolated from fixture startup. Deterministic Rust tests separately cover
  all retry paths, cancellation/exhaustion/replay guards, overdue notices and
  actual delegated status delivery without a runtime observer.

Retry eligibility, delay policy, usage, credit recovery, request budgets,
work-slot ownership and human-blocker controls are unchanged. No new dependency,
configuration key, store schema or MSRV change. Optional activity data remains
compatible with older saved snapshots and clients. Internal Cargo requirements
match the workspace release version.

The distinction between dispatch/status and substantive progress was reviewed
against pinned Hermes auxiliary hooks. This is an independent Rook retry-status
implementation, not a port of a Hermes retry-observation API. See
[reference credits](../../references/PORTED.md), the
[runtime contract](../provider-retry-observation.md) and the
[owned fixture](../../xtask/probes/provider-wait/README.md).

Publication requires full preflight before the version bump, eight required jobs
on the final versioned source, five downloaded archive/provenance/skills/linkage
checks, both host versions and126 native conditions on the extracted Windows
package: managed work22, background installation10, release metadata6, independent
publication8, ACP28, credit10, HTTP-date8, checker history10, concurrent retries8
and provider waits16. Publish the same tested draft, then compare all six
anonymous public assets. See [release verification](../releasing.md).

Optional real-model smoke remains separate evidence, including failures. Scripted
fixture success does not establish real-model task quality or production
throughput. The real-transcript compaction experiment remains pending and the
default summary allowance remains2048. No installed user daemon, session, state
or cache is updated by these release checks.
