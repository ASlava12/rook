# Rook 0.21.2

- A stream ending without confirmed completion can no longer execute complete-
  looking tool calls or finish the task. Partial text and reported usage remain
  saved with incomplete receipts; unconfirmed signed assistant state is withheld
  from replay. A recognized finish reason without `[DONE]` remains sufficient
  where supported. Managed pause and cancellation retain priority.
- Unconfirmed compaction text uses the existing source-log fallback instead of
  becoming a successful summary. A forced final answer without terminal evidence
  cannot replace an explicit output artifact. Reported usage is retained in both
  paths, along with effects from earlier confirmed steps.
- A slow language-server initialization no longer holds the whole workspace's
  server registry. Ready clients, write diagnostics and another language's
  startup remain available. Concurrent callers for one language still share
  one physical initialization or one cached failure.
- Generic symbol queries prefer an initialized client with an observed live
  process. An exited cached client returns a closed error and cannot hide
  another startable language. Process liveness is not an RPC-health guarantee;
  this does not automatically restart failed language servers.
- Repeated cold diagnostic requests retain at most one background warm task
  per configured language. Shutdown refuses newly arriving starts without
  waiting for an unrelated handshake, waits for admitted initializations and
  can be retried after cancellation without skipping remaining clients.
- Language-server downloads and self-update checks reject release tags that
  are not single portable directory names. Applying a saved or constructed
  update check revalidates its tag before fetching or cleaning staging files.
  The policy accepts up to 255 ASCII letters, digits, `.`, `_`, `+` and `-`,
  excluding `.`/`..`, trailing dots and Windows device names. Other tag shapes
  are deliberately refused before writing files.
- New owned package probes exercise shared LSP startup through six ordinary
  daemon chat sockets, malformed release metadata through the CLI, and missing
  model-terminal evidence through three more ordinary chats. They use
  isolated state and local scripted services, without a live model or changes
  to an existing installation.

There are no new configuration keys, dependencies, stored formats or tool names.
LSP startup failures remain cached until a new pool is constructed. Installation
deduplication and real-server indexing performance are separate concerns.

See [LSP startup](../lsp-startup-concurrency.md) and
[model-terminal admission](../model-terminal-admission.md), alongside
[release verification](../releasing.md) for behavior and verification limits.
The startup design independently adapts a per-server in-flight pattern reviewed
in historical OpenCode source. Terminal admission adapts a finish-before-done
check reviewed in pinned Pi to Rook's own completion metadata and effects boundary.
No upstream code is copied and reference pins are unchanged.
