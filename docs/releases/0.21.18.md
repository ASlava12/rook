# Rook 0.21.18

Skill search now distinguishes an incomplete search from a successful search with no matches. The model receives source errors alongside partial results; CLI users can request the same detail with `rook skills search --json --diagnostics`. The existing `--json` array format remains available without that option.

Known connection credentials are masked in saved tool calls, tool results and later model context, including their standard JSON and Rust debug representations. Resolved provider credentials reach the agent vault through selection, retries, limits and fallback wrappers; the shared factory also registers environment shorthand keys in the supplied vault for auxiliary and compaction routes. Tool execution and HTTP authentication retain their original values. This covers known values of at least six bytes; arbitrary encodings and unknown secrets are outside this change.

Z.ai HTTP 429 refusals with structured code `1113` and the documented insufficient-balance message return immediately instead of spending time on transient retries. Configured fallback routes remain eligible. Temporary rate and usage-window refusals retain their retry behavior.

Repeated compaction with no new history to summarize no longer makes another summary request or replaces the previous summary. The saved summary and source boundary remain intact.

Implementation and audit references: pinned Pi and Hermes revisions are recorded in `references/PORTED.md`. Rook's implementations are independent.

See [skills](../skills.md), [Z.ai refusals](../zai-account-errors.md),
[compaction](../long-task-compaction.md) and the [credential contract](../adr/0013-secrets-are-named-never-valued.md).
No dependency or minimum Rust version change is included.
