# Rook 0.18.0

- `tool_status` explains current-session tool availability, including configuration,
  input/depth/recipe limits and deferred MCP tools, without probing or granting access.
- `post_compaction` hooks observe committed summary/fallback records with metadata.
- `session_delete` hooks observe explicit deletion once, including empty sessions;
  retries and automatic retention cannot repeat them.
- Skill discovery and bundled-resource enumeration now have aggregate admission
  limits and explicit incomplete/error reports.
- Managed stages retain interrupted-owner receipts across process loss and park
  repeated recovery at `work.restart_limit`; explicit resume resets the guard.

Seven reference pointers advance; three already match their fetched tips.
Stored JSON remains compatible with earlier records. Observer callbacks are
best-effort and process-local; their output cannot change context or decisions.
`Skill::resources` now returns a fallible result for oversized/unreadable trees.
Model-quality and compaction-output defaults are unchanged.

See [contracts and validation](https://github.com/ASlava12/rook/blob/v0.18.0/docs/reference-followup-20261018.md) and the
[frozen review](https://github.com/ASlava12/rook/blob/v0.18.0/docs/research/reference-review-20261018-followup.md).

Validation: the complete local `cargo xtask ci`, browser module suite and native
CLI/daemon/Chrome/PTY probe passed, including real isolated-daemon process kills.
Required platform CI is checked on the exact source commit before tagging;
published host binaries are checked separately. Model fixtures do not establish
a model-quality improvement.
