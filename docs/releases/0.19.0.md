# Rook 0.19.0

- Managed root work can call `defer_work` to save a timed checkpoint, release its
  executor after turn closing, and resume the same transcript when due.
- Tool completion, execution receipt and the wait commit atomically. Restart
  recovery preserves the deadline and previous file effects; an exact retry
  cannot extend it.
- Existing iteration/token/lifetime budgets, recipes, policy, pause/cancel and
  identified controls remain effective. A late response cannot undo newer user
  controls or abandon running scoped children.
- CLI/API/TUI/browser distinguish a saved wait from a running executor. Open chat
  observers follow the next owner, and early `/continue` queues behind occupied
  daemon capacity.

Four reference pointers advance after reviewing 18 incoming commits. Optional
JSON fields preserve older run reads; stored postcard layouts are unchanged.
Unknown external hook effects still require recovery inspection. The daemon must
be running to execute a due continuation.

See the [behavior and verification contract](https://github.com/ASlava12/rook/blob/v0.19.0/docs/deferred-work.md)
and [frozen source review](https://github.com/ASlava12/rook/blob/v0.19.0/docs/research/reference-review-20261018-after018.md).

Validation includes managed-engine/policy/recovery checks, browser modules and an
owned native HTTP/CLI/WebSocket/process-loss probe. The complete local gate and
required exact-revision platform CI are checked before tagging; public archives,
bundled skills and the published host binaries are checked separately. Model
fixtures do not establish a model-quality improvement.
