# Rook 0.21.1

- A managed conversation waiting for an ordinary retry releases its execution
  slot, allowing unrelated work to run. When its deadline arrives or fresh user
  guidance wakes it, the conversation reacquires capacity before calling the
  model. Its session, attached observers and queued messages are retained.
- Due schedules can launch while another goal waits for a future retry. Pause,
  explicit resume, human blockers and deferred checkpoints retain their controls.
  Expected waits remain visible, and overdue scheduling is still monitored.
- Skill descriptions in terminal listings and search retain whole grapheme
  clusters and use terminal display width for truncation and column padding.
  Accented text, joined emoji and wide characters no longer produce split
  previews or overrun the description column. JSON keeps the full description.
- macOS process-group inspection distinguishes confirmed zombies from live
  descendants, allowing command cancellation and inspected shell-undo recovery
  to finish without waiting for dead processes to be reaped. Incomplete native
  inspections remain unknown; recovery still requires explicit acknowledgement.
- Tagged release workflows verify all collected archives before creating the
  draft: checksums, portable paths, file layout, bundled skills, source/build
  provenance, architecture and runtime linkage. Downloaded-package and native
  runtime checks still precede publication.

There are no new configuration keys or stored-format changes. Existing explicit
interactive-chat admission policy is unchanged; managed execution capacity counts
occupied slots rather than live waiting control owners. Health `turns_running`
continues to count those owners and can exceed the managed execution-slot limit.

See [retry capacity](../managed-retry-capacity.md),
[guidance during retry waits](../managed-retry-guidance.md),
[macOS process groups](../macos-process-groups.md), and
[release verification](../releasing.md) for behavior and verification limits.
The capacity design, skill previews and process-state checks independently adapt
ideas reviewed in pinned Pi, Goose and OpenClaw references. No upstream code is
copied and reference pins are unchanged.
