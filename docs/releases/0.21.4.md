# Rook 0.21.4

- Independent cooperating installers now hold a kernel lease while changing the same cache/command. Release bytes must pass digest verification before ownership files or package directories are created; command builds acquire ownership before creating their prefix or launching their builder. Different commands and cache roots remain independent. Waits are cancellable and bounded, and process loss releases the lease without deleting or stealing its stable coordination file.

- ACP preserves successful JSON-RPC null acknowledgements and accepts null/omitted default session-list requests. Invalid write acknowledgements and required file/terminal payloads retain their method-specific validation.

- Editor writes or terminal commands whose result cannot be proven now retain durable unknown-effect recovery. Missing acknowledgements, unusable terminal identity, malformed output or missing exit evidence cannot silently become safely completed failures. Closing the transport preserves the operation; a fresh process keeps writes blocked until explicit review. Inspection remains available and does not acknowledge the effect.

- Terminal results use confirmed exit evidence from output or the flattened wait response. Signal termination and unsigned 32-bit failure codes remain known failures. Normal null cleanup acknowledgements retire the guard; malformed cleanup acknowledgements keep cleanup active without discarding an already confirmed command result.

- The compaction A/B example admits all fixtures before generation and measures only committed, nonempty summaries with complete model receipts and reported usage. It retains failed-arm diagnostics, distinguishes admitted output allowance from transport limits, and records termination and text/reasoning byte counts. This corrects experiment admission and reporting; the default summary budget remains 2048 and the real-transcript quality comparison is still pending.

- Model smoke scenarios use their owned configuration, require completed model-pull responses and confirm the requested model is available. Bounded failure excerpts retain late evidence and child checks. Windows HTTP fixtures explicitly restore blocking accepted streams rather than increasing their deadlines.

No new dependency, agent configuration key, database format or MSRV change. Cache
ownership creates stable zero-byte coordination files under the cache's private
.install-locks directory. Cross-process downloads remain independent; legacy/external
writers and transactional multi-file reads are outside this coordination contract.

The install ownership design extends the reviewed historical OpenCode pattern. ACP
payload handling follows the pinned ACP schema and client response contracts. Reference
pointers remain unchanged, and no upstream implementation is copied.

Source preflight completed formatting, workspace/all-target clippy, current frontend
builds and the complete workspace test suite on Linux. The same source passed the owned
ACP probe on Linux, Windows and macOS, the independent installer probe on Linux and the
compaction comparison probe on Linux. These scripted checks establish runtime/protocol
behavior, not live-model task quality or a completed real-transcript summary experiment.

Publishing requires all eight required jobs on the final versioned source, all five
downloaded archive/provenance/linkage checks and native checks on the extracted host
package. See [release verification](../releasing.md) and the published release's
[publication record](0.21.4-verification.md).
