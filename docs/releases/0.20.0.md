# Rook 0.20.0

- Root managed stages can call `block_work` to save a human prerequisite and
  stop until explicit user resume. Restart alone keeps the goal blocked.
- The reason, tool result, execution receipt and managed state commit atomically.
  Explicit resume retains the same transcript and prior tool results. Remaining
  calls in the blocked batch are skipped.
- An invalid or unavailable completion classifier retries the saved reply's
  classification instead of rerunning the working turn. Repeated unresolved
  failures park the goal after three attempts, independently of its iteration
  limit and retry window.
- Completion classification has a 4096-token output allowance, bounded by
  remaining spend, and explicitly distinguishes required user actions from
  optional follow-up work. A recovered finish verdict still requires independent
  goal verification.

Policy, recipe scopes, scoped children, generation-bound controls, final-output
contracts and recovery of unknown external effects remain enforced. The existing
CLI/API/TUI/browser goal status shows the saved blocking reason. There is no new
stored postcard layout or public status variant.

The checkpoint design independently adapts Pi's committed task states at pinned
`482c1381a00d8d00bc81697e4a980c593db6803e`; no upstream code is copied.
See the [behavior and verification contract](../managed-blockers.md).

Verification covers managed-engine persistence, policy and control races,
ordinary agent loops, output contracts and an owned HTTP/daemon restart probe.
Required platform checks are inspected on the tagged source; package contents,
checksums and the host binaries are verified separately. The
[cycle ledger](../reference-cycle-20261021.md) records results and limitations,
including the nonblocking 3B-model smoke failures.
